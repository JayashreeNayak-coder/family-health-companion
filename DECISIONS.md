| D-028 | 2026-11-10 | Owner's request and choices: password reset by emailed link, sent through Gmail SMTP (`spring-boot-starter-mail`); Google sign-in through Spring Security OAuth2 client (`spring-boot-starter-security-oauth2-client`), on only when its keys are set. | D-029 | 2026-11-10 | Phase 17 (emergency card), plan approved by the owner. A card holds up to 30 lines of approved text, of six kinds: a name, allergies, conditions, medications, emergency contacts, and other information. A line copied from a record keeps that record's ID and change time, never shown publicly, so the owner's screen can flag a record that changed or was deleted; the public card keeps the approved text. Turning the card off forgets the token hash, so turning it on again always makes a new link. The link's token is in the `#` part (`/emergency-card#<token>`), so loading the page sends it to no server log; the page then reads `GET /api/v1/public/emergency-cards/{token}`, limited to 30 reads a minute per IP address. Views are not audited (anyone could fill the table); changes are. QR codes come from `qrcode-generator` 2.0.4 (MIT, no dependencies, own types), drawn as SVG from its module grid. The plan named `qrcode`, but it pulls in three packages, including a command-line parser. | Owner approved the plan and the QR library on 2026-11-10. `docs/04` section 7, `docs/05` section 8, `docs/06` section 6. |
| D-030 | 2026-11-10 | The backend logs at startup whether Google sign-in and email are on, and signs in to the mail server once (sending nothing) to report wrong credentials. | D-031 | 2026-11-10 | Owner's request and choices: managers can rename a family and delete it. A family's name is unique among the families each account belongs to, ignoring case and spacing, checked on create, rename, and joining; app-wide uniqueness was rejected because it would reveal other users' family names and block common names. Deleting is allowed only when the manager is the family's only member, so no other adult's profile is destroyed; the screen asks for the family name to be typed. Profiles and families can have a photo: JPEG or PNG up to 5 MB, re-encoded on the server with the JDK's image tools (no new dependency) as a 512 px square JPEG, which drops EXIF location data. Profile photos need `EDIT` to change and `VIEW` to see; family photos need a manager to change and membership to see. | Owner's request on 2026-11-10, choosing the recommended options. The name check spans memberships, so it is a service check, not a database constraint; two simultaneous requests could slip past it. |
| D-032 | 2026-11-10 | Phase 18: summary PDFs are made on the server with Apache PDFBox 3.0.7 (Apache-2.0), chosen by the owner over OpenPDF and browser printing, with Noto Sans Regular and Bold (SIL OFL 1.1, licence in `resources/fonts/OFL.txt`) embedded as subsets. PDFBox does no text shaping, so scripts such as Devanagari can't be shown correctly; characters the font lacks print as "?". | D-033 | 2026-11-11 | Phase 3 hosting, owner's choice, all on free plans: Cloudflare Pages (frontend), Render (backend, Docker, `render.yaml`), Neon PostgreSQL 18, Cloudflare R2 (files). The owner chose free Render with an HTTPS email API over paid Render ($7 a month) with Gmail SMTP, because Render's free plan blocks SMTP ports; Brevo is the email API, the only free option found that sends to any address without a domain of one's own (300 a day; a Gmail sender is replaced, so mail may land in spam). The backend's public address refuses requests without `PROXY_SECRET` (except the health check) and takes the visitor's address from `X-Client-IP`, set by the proxy. Files go to R2 through `S3DocumentStorage`, using the AWS SDK's S3 client 2.57.5 (Apache-2.0) with the JDK-based HTTP client instead of Netty or Apache; local disk stays the default when no bucket is set. Email goes through `BrevoEmailSender` when `BREVO_API_KEY` is set, with no SDK. The Docker image limits the heap for 512 MB. Registration is limited to 20 an hour per address, closing the item `docs/06` required before going online. | Owner's choice on 2026-11-11, with the recommended options. Synthetic data only. Neon's 100 compute hours a month allow about 400 hours of uptime, so no keep-alive pinger. |
